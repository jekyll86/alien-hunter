# Communication & Code Guidelines

## 1. Tone and Style
- **Concise & Direct**: Keep all text, explanations, and documentation brief and focused. Avoid unnecessary preambles or verbose recaps.
- **Concise Code Comments**: Write brief, technical comments and docstrings. Focus only on non-obvious architecture or protocol quirks; avoid restating self-evident code.
- **No Buzzwords or Exaggerated Claims**: Strictly avoid marketing jargon, buzzwords, and promotional claims (e.g., "blazing fast", "state-of-the-art", "cutting-edge", "revolutionary", "game-changer", "ultra", "near-100%").
- **Neutral, Natural, and Technical**: Always use a calm, factual, and objective engineering tone. State technical facts, trade-offs, and protocol specifications cleanly without hype.
